# 多语言与翻译贡献

MintSoda 的 WebUI 使用 [vue-i18n](https://vue-i18n.intlify.dev/) 管理界面文案，语言选择保存在浏览器本地，首次访问时按浏览器语言自动匹配，无法匹配时回落到简体中文。切换语言后会刷新页面，以便模块级常量（设置页标签、排序项、主题预设等）一同重建，同时切换 Element Plus 与 dayjs 的语言包；整个过程不会改动服务端配置。

## 内置语言

| 代码 | 名称 | 说明 |
| --- | --- | --- |
| `zh-CN` | 简体中文（中国大陆） | 源语言，所有键以此为准 |
| `zh-TW` | 繁體中文（台灣） | 由源语言转换并校对台湾用语 |
| `en-US` | English | 英文翻译 |

`zh-CN` 是唯一的事实来源：新增文案必须先写在这里，其他语言缺失时自动回落到 `zh-CN`。

当前词条约 803 条，三种语言的键必须完全一致。新增文案时优先复用已有键，不要为同一句话再建一份。

## 目录结构

| 路径 | 说明 |
| --- | --- |
| `mint-soda-ui/src/i18n/index.js` | 创建 i18n 实例、语言列表、语言检测与切换 |
| `mint-soda-ui/src/i18n/element.js` | Element Plus 与 dayjs 的语言包映射 |
| `mint-soda-ui/src/i18n/locales/zh-CN.js` | 源语言词条 |
| `mint-soda-ui/src/i18n/locales/*.js` | 其他语言词条，键必须与 `zh-CN.js` 一一对应 |
| `mint-soda-ui/src/view/custom/LocaleSwitcher.vue` | 登录页、初始化页与侧栏共用的语言选择器 |

## 在页面中使用

组件内统一使用 `vue-i18n` 的 `useI18n()`：

```vue
<template>
  <el-input :placeholder="$t('search')"/>
  <span>{{ $t('nsubscriptions', {n: total}) }}</span>
</template>

<script setup>
import {useI18n} from "vue-i18n"

const {t} = useI18n()
</script>
```

模板里使用 `$t`，脚本里使用 `t`。纯工具模块（如 `src/js/format.js`）不在组件上下文中，直接从 `@/i18n/index.js` 引入导出的 `t`：

```js
import {t} from "@/i18n/index.js"

export const label = () => t('justnow')
```

## 键命名规则

- 键是英文短语去掉分隔符后的小写形式，例如 `Download settings` → `downloadsettings`；超长或重复时追加 `-2`、`-3` 等后缀。
- 插值使用具名参数并写成 `{n}`、`{name}`、`{list}` 等，不要拼接字符串再拼接语序。
- 文案中的 `{n}` 占位符在各语言中必须保持一致，缺失会导致运行时插值失败。
- 只翻译界面文案。配置枚举值、RSS 字段、通知模板变量（`${title}` 等）、下载路径与 `config.js` 中的默认数据值不要翻译。

## 新增或修改文案

1. 在页面中改用 `$t` / `t`，不要把中文直接写进模板或脚本。
2. 在 `zh-CN.js` 中补充键值；若同一文案已存在，复用已有键，避免重复。
3. 同步补齐其他三种语言。暂时无法翻译时可先复制源语言，后续再校正，但不要留空字符串。
4. 修改带占位符的文案时，检查所有语言里的占位符是否一致。
5. 运行 `cd mint-soda-ui && ./node/pnpm.cmd build`（Linux 下为 `pnpm build`）确认构建通过。
6. 模块级常量（如设置页标签数组）在模块加载时求值，切换语言后依靠页面刷新重建；新增这类常量时不要再手工监听语言变化。

## 新增一种语言

1. 在 `src/i18n/locales/` 新建 `<code>.js`，复制 `zh-CN.js` 的结构并翻译所有值。
2. 在 `src/i18n/index.js` 的 `messages` 中注册该词条模块，并在 `locales` 数组中加入 `{code, label}`，顺序即语言选择器的展示顺序。
3. 在 `normalize` 中补充该语言的浏览器语言匹配规则，让首次访问可以自动识别。
4. 在 `src/i18n/element.js` 中为 `ELEMENT_LOCALES` 与 `DAYJS_LOCALES` 添加映射；没有对应语言包时回落到最接近的语言。
5. 若右侧语言名称较长，确认侧栏与移动端底部导航不被裁切。

## 常见问题

**切换语言后部分文案没变**：这类文案通常来自模块级常量（设置页标签、排序项、星期名、主题预设），它们在模块加载时求值。语言切换会刷新页面重建这些常量；如果是新写的常量，确认没有在模块顶层捕获旧的 `t`。

**页面报 `Invalid token in placeholder`**：文案里出现了 vue-i18n 不认识的 `{` 或 `}`。普通花括号必须转义，见上文占位符说明；HTML 标签也不要写进词条，改为纯文本。

**某条文案在运行时变成空字符串**：多数是 `$` 或 `{` 未转义导致编译失败。用 `{'$'}{'{'}name{'}'}` 形式表示字面的 `${name}`。

**中文逗号、全角括号要不要保留**：保留。标点是文案的一部分，三种语言各自使用本语言的标点习惯。

## 校对与验证

- 简体中文以 `zh-CN` 为准；繁体与英文改动需要保证术语一致，例如 `Subgroup` 在繁体统一为「字幕組」。
- 界面中所有可见文案都应来自词条；残留的硬编码文案可以用 IDE 搜索中文正则（如 `[一-龥]`）快速定位，`src/js/ani.js` 与 `src/js/config.js` 中的默认数据值属于已知例外。
- 语言切换后重点检查设置页标签、长按钮、表格表头、弹窗标题与移动端底部导航的换行与截断。
- 提交信息使用 Conventional Commits，翻译修正建议使用 `fix(i18n): ...`，新增语言使用 `feat(i18n): ...`。

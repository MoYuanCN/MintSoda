## 运行与配置文件

MintSoda 只面向 Windows 和 Linux。发布页提供 Windows EXE 与 JAR，以及 Linux 使用的 JAR。运行 JAR 需要 Java 25。

- **Windows EXE**：配置文件保存在 EXE 同目录下的 `config/`。首次运行会创建该目录。检测到旧版 `%USERPROFILE%/mint-soda/` 配置且目标目录还没有配置文件时，程序会复制旧配置；原目录会保留。
- **Windows 或 Linux 的 JAR**：若设置了 `CONFIG` 环境变量，则使用该目录；否则当前目录存在 `config/` 时使用它。Windows 没有上述目录时使用用户目录下的 `MintSoda/`（检测到旧的 `mint-soda/` 配置会自动复制）；Linux 使用当前工作目录下的 `config/`。
- **Linux 一键安装**：`curl -fsSL https://raw.githubusercontent.com/MoYuanCN/MintSoda/main/linux/install.sh | sudo bash` 会把 JAR 安装到执行命令时所在的目录（不新建子目录）并注册 systemd 服务。安装过程中会在终端依次询问用户名与两次密码（密码输入时不回显）：用户名需 3-32 位字母、数字、下划线或连字符，密码至少 8 位且包含大写字母、小写字母、数字、符号中的至少两类；直接回车跳过则由程序在首次启动生成随机凭据。也可用 `--username` / `--password` 直接传入，或用 `--setup` 在尚未配置账号时跳过询问并在 WebUI 中完成初始化，`--port` 修改端口，`--dir` 指定目录，`--yes` 跳过所有确认。安装完成后运行 `mintsoda` 打开管理菜单，可查看运行状态、版本、更新、启停和日志，也可直接使用 `mintsoda status` 等命令。
- **Linux 固定目录安装**：`sudo bash linux/install-legacy.sh` 会把服务安装到 `/opt/mint-soda/`。安装脚本需要联网下载 JAR 和 Java 25。

配置目录的位置取决于启动方式：

| 启动方式 | 配置目录 |
| --- | --- |
| Windows EXE | EXE 同目录的 `config/` |
| JAR，设置了 `CONFIG` | `CONFIG` 指向的目录 |
| JAR，当前目录存在 `config/` | 当前目录的 `config/` |
| Windows JAR，以上都没有 | 用户目录下的 `MintSoda/`（检测到旧的 `mint-soda/` 会复制） |
| Linux JAR，以上都没有 | 当前工作目录的 `config/` |

配置目录只保存设置文件 `config.json`。其余数据统一放在配置目录同级的 `data/`：订阅、封面与预览图缓存、上传图片、种子、插件与日志都在这里。备份与迁移时整体复制 `config/` 与 `data/` 即可；各配置字段的含义见[配置参考](CONFIG.md)。从旧版本升级时，原配置目录内的 `config.v2.json`、`ani.v2.json`、`files/`、`img/`、`ui-assets/`、`plugins/`、`torrents/`、`logs/` 会在启动时自动迁移到新结构。

首次启动不再内置 `admin/admin`：

- **Windows**：程序会自动打开浏览器并显示“初始化登录账号”页面，用户名需为 3-32 位字母、数字、下划线或连字符，密码至少 8 位并包含大写字母、小写字母、数字、符号中的至少两类。完成前无法登录。
- **Linux**：启动时自动生成随机用户名与强密码，并只在首次启动的日志中输出一次；请立即保存，后续启动不会再次显示。
- **环境变量覆盖**：设置 `MINT_SODA_USERNAME` / `MINT_SODA_PASSWORD` 可强制覆盖登录凭据，每次启动都会生效；密码不满足强度要求时程序拒绝启动。

初始化完成后即可登录，再配置 qBittorrent 的地址和认证方式。设置页同样会校验用户名与密码强度，修改后所有已登录会话失效。

## 设置页

设置页按用途分为四组，左侧导航切换页面，底部常驻保存条：

| 分组 | 页面 | 内容 |
| --- | --- | --- |
| 常用 | 外观与主题 | 主题模式、强调色、质感预设、背景与 Logo、布局与自定义样式 |
| 常用 | 订阅与更新 | RSS 刷新间隔与并发、集数处理、完结迁移、备用 RSS、新订阅默认规则 |
| 常用 | 命名与路径 | 重命名模板、文件名处理、普通/剧场版/合集保存位置 |
| 常用 | 下载与任务 | qBittorrent 连接与认证、任务执行、清理规则、优先保留、限速与做种 |
| 规则 | 匹配规则 | 全局排除、全局匹配、反匹配 |
| 规则 | 通知 | 通知模板、状态样式与各通知渠道 |
| 服务 | 元数据来源 | Mikan、Bangumi、TMDB 与 GitHub Token |
| 服务 | 网络与代理 | 代理设置与连通性测试 |
| 服务 | 安全与访问 | 登录账号、会话、IP 白名单、反向代理与 API Key |
| 服务 | 系统与维护 | 备份、缓存、日志、自启与自动更新 |
| 其他 | 开发者 / 关于 / 捐赠 | 诊断选项、版本与更新、项目支持 |

- 修改只停留在浏览器中，点击底部“保存设置”或按 `Ctrl + S` 才写入配置并生效。
- 顶部显示“已保存”或“N 处未保存”，有改动的页面在导航上显示小圆点；`撤销修改` 丢弃全部未保存改动。
- 搜索框可按页面名称与关键字（如“间隔”“通知”“代理”）过滤导航。
- 保存前会校验：刷新/重命名间隔至少 1 秒，RSS 并发在 1-16 之间，JSON 模板必须是合法 JSON。
- 账号密码留空表示不修改；修改用户名或密码后所有会话失效，需要重新登录。
- 有未保存改动时离开设置页会提示确认，确认后改动被丢弃。
- 开发者选项与 Bangumi 授权回调各自只保存所需部分。

## qBittorrent

在“设置 → 下载与任务”中配置 qBittorrent 地址和认证方式：

- **API Key**：用于支持 API Key 的 qBittorrent 服务。
- **用户名密码**：用于未提供 API Key 的服务，程序使用 qBittorrent WebUI 登录认证。

两种方式互斥。MintSoda 只支持 qBittorrent，也不提供集成的任务进度页面；任务和进度请在 qBittorrent 中查看。

## 添加订阅

“添加订阅”弹窗提供三种来源：Mikan、AniBT 和“其他”。

- **Mikan / AniBT**：点击“浏览”从站点列表中选择番剧与字幕组，会自动带入 RSS 地址、Bangumi 条目和字幕组。
- **其他**：手动填写番剧名称、Bangumi 地址和 RSS 地址，适合任意第三方 RSS。

同一番剧存在多个字幕组时，可以一次性加入批量确认弹窗，逐条调整后再添加。

## RSS 刷新

在“设置 → 订阅与更新”中设置 RSS 刷新间隔，单位为秒，最小值为 1 秒。请结合 RSS 站点访问频率和网络环境设置合理间隔。

刷新行为：

- 间隔按“上一轮开始时间”计算，本轮处理耗时不会叠加到等待时间上；若处理时间已经超过间隔，会先短暂停顿再开始下一轮。
- 同一轮刷新会先并发拉取所有 RSS，再逐个订阅做本地解析。并发数可在“RSS并发”中设置，默认 4，范围 1-16；间隔很短时建议保持较小值。
- 相同 RSS 地址在同一轮只请求一次；跨轮会携带 `ETag` 做条件请求，服务端返回 304 时直接复用上次内容。
- RSS 请求失败时会沿用上次成功的内容，并在短时间内退避，避免短间隔轮询持续请求异常站点；没有历史内容时本轮跳过该地址。
- “RSS超时”是单个请求的最长等待时间，默认 20 秒。
- 一轮刷新结束时才统一保存订阅进度，避免短间隔下每个订阅都触发一次写盘。

旧配置中的分钟间隔会自动转换为秒。配置升级后可以在设置页确认刷新间隔。

订阅页顶部提供排序下拉，可临时按评分、拼音、标题、更新时间、更新星期或备用 RSS 数量排序；默认排序在“设置 → 外观与主题 → 布局与行为”中配置，临时切换不会改动默认值。

## 插件

侧栏“插件”页可以扩展通知渠道、订阅过滤、订阅事件、周期任务、模板变量、下载拦截、下载事件与插件自有接口。

- **安装**：上传 `plugin.jar`（Java）或 `plugin.zip`（JavaScript / Lua），或在“插件市场”中填写市场索引地址后安装。安装后需手动启用。
- **三种运行时**：Java 插件功能最全；JavaScript 与 Lua 插件不需要编译，适合改模板、加通知渠道与简单过滤。
- **权限**：每个插件卡片有“权限”一栏，按「订阅 / 下载与通知 / 任务 / 接口 / 配置与数据 / 系统」分组逐项开关，读与写分开授权（例如插件可以只读数据不能写入）。取消下载是独立权限，未授权时插件无法中断下载。保存后已启用的插件会立即按新权限重载；关闭的权限对应功能会停止工作，插件其余部分继续运行。安装时按插件声明初始化，升级不会重置你的调整。
- **插件数据**：插件可在自己的 `plugins/{插件标识}/data` 目录保存状态，升级与重装都不会丢失；卸载会连同数据一起删除，需要保留时先导出备份。
- **备份**：导出的设置备份同时包含插件与插件私有数据；导入会整体替换插件目录，插件按备份内容恢复但默认停用，权限仍以本机记录为准。备份文件名形如 `MintSoda.backup.<版本>.zip`，日志文件位于配置目录的 `logs/MintSoda.log`。
- **市场**：市场地址保存在设置中，是一个 JSON 索引；检查更新时优先使用市场条目，缺少条目时回退到插件自带的更新地址。
- **更新**：插件卡片显示“可更新”与最新版本，可单个更新或一次检查全部插件。
- **配置**：插件可以在插件页声明设置项，保存后会写入插件配置。
- **通知渠道**：启用提供通知渠道的插件后，在“设置 → 通知”的通知类型中选择“插件渠道”，再选择具体渠道并填写其字段。
- **模板变量**：插件可向通知、重命名与下载路径模板追加 `${xxx}` 字段，写法与内置字段一致。
- **下载拦截与下载事件**：下载拦截可在提交下载器前改写保存位置或名称，也可以直接取消某个任务；下载事件只会收到任务提交、完成与失败的通知，不会改动任务。
- **插件接口**：插件页会显示插件注册的接口路径，统一挂在 `/api/plugin/api/{插件标识}/` 下，调用需要登录。
- **插件页面**：提供页面的插件会在卡片下方显示「插件页面」按钮，点进去就是插件自己的页面（`#/plugins/{插件标识}/{页面标识}`）。页面由主程序按白名单区块渲染，插件不注入 HTML 或脚本；表格与表单的数据通过插件接口读取与提交，同样需要登录。

安装与更新都会校验 sha256 与文件大小，地址限公网 `http`/`https`。插件与服务同权限运行，只安装可信来源的插件。插件开发方式见 `docs/PLUGIN_DEVELOPMENT.md`。

## 缓存清理

“设置 → 系统与维护 → 缓存”可以手动清理未被引用的封面与预览缓存。“自动清理缓存”默认关闭，开启后按设定的小时数（默认 72 小时）定期清理，间隔范围 1-720 小时。

## 合集下载

“合集”页上传种子并选择 Bangumi / TMDB 条目后即可下载整季。保存位置会在名称、TMDB、字幕组、季、日期或剧场版标记变化时自动重新计算，也可以点击下载位置旁的刷新按钮手动更新。

“设置 → 命名与路径 → 合集保存位置”可以为合集单独指定目录，例如常规保存位置是 `/番剧/更新中`，合集可以保存到 `/番剧/合集`：

- 支持与普通保存位置相同的变量，例如 `${title}`、`${season}`、`${year}`、`${quarterName}`。
- 留空表示不启用，合集使用添加合集时显示的路径；填写的是固定路径（不含变量）时，开始下载会按当前名称重新计算，避免沿用旧名称。
- 启用后，添加合集弹窗中的下载位置输入框只读，并提示正在使用合集保存位置。
- 该设置只影响合集下载，不影响普通 RSS 订阅。

## 重命名和保存路径

全局重命名模板和下载路径可在“设置 → 命名与路径”中修改；单条订阅可以启用自定义重命名模板或自定义保存路径。模板至少保留集数标记 `S${seasonFormat}E${episodeFormat}` 或 `S${season}E${episode}`，避免无法识别剧集编号。启用“已下载文件自动跳过”时，也要确认 qBittorrent 保存路径与 MintSoda 配置的下载路径一致。

## 标题匹配规则

规则入口包括“设置 → 匹配规则”（全局排除 / 全局匹配 / 反匹配），以及每条订阅的编辑窗口。匹配和排除规则按 RSS 条目标题判断，也可使用 `{{字幕组}}:正则` 限定来源字幕组。反匹配规则单独设置标题正则和目标字幕组：标题命中后，条目会归入该规则指定的字幕组，不要求原 RSS 已带有该字幕组。

### 规则优先级

实际下载和合集预览共用相同的规则判断：

| 顺序 | 规则 | 行为 |
| --- | --- | --- |
| 1 | 本地或全局反匹配命中 | 直接接收条目，并归入命中规则指定的字幕组。该命中优先于普通匹配与排除。多条命中时按规则列表顺序取第一条。 |
| 2 | 反匹配已启用但未命中 | 默认跳过。可在该订阅中改为“继续普通匹配规则”或“直接放行”，订阅未单独指定时跟随“设置 → 反匹配”的默认行为。 |
| 3 | 订阅本地“匹配” | 配置了多条规则时，每条规则都必须命中。 |
| 4 | 全局匹配 | 仅在该订阅启用全局匹配时生效；每条适用规则都必须命中。全局匹配通过后优先于排除规则。 |
| 5 | 本地排除和全局排除 | 命中任意适用的排除规则则跳过。全局排除需在订阅中启用。 |

反匹配规则之间是“任意一条命中”；本地匹配和全局匹配的规则之间是“每条都命中”。如果没有启用反匹配、全局匹配或排除规则，普通订阅行为不受影响。

### 全局反匹配

在“设置 → 匹配规则 → 反匹配”中维护共享规则，并用测试区检查标题。之后编辑订阅，在“反匹配”页开启“使用全局反匹配规则”。全局规则不会自动应用到所有订阅。

每条订阅也可维护自己的反匹配规则。两处规则共同生效，任意一条命中即可。反匹配未命中行为按订阅设置，默认是“跳过，不下载”。启用反匹配但没有填写规则时也会按未命中处理。

#### 用字幕组“反匹配”标记订阅

添加或编辑订阅时，把“字幕组”直接填成 `反匹配`（也接受 `REVERSE_MATCH`），这条 RSS 就会进入反匹配模式：

- 条目命中任意一条本地或全局反匹配规则时，自动归入该规则指定的目标字幕组，并记录到订阅中。
- 命中的字幕组会按集数长效保存，之后重新解析、重启或再次刷新都沿用已记录的结果，不会因为当轮标题格式变化而丢失。
- 在订阅的「反匹配」页可以看到已命中的每个字幕组及其集数范围，并能给每个字幕组单独设置集数偏移。该偏移叠加在订阅的集数偏移之上，只影响这个字幕组的条目，适合不同字幕组集数编号不一致的情况；填写 0 表示不额外偏移，保存订阅后生效。
- 没有命中任何反匹配规则的条目按“反匹配未命中行为”处理，默认不下载。
- “反匹配”只是开关，不是真实字幕组，不会写进下载标签、重命名或保存路径。

该行为可在“设置 → 匹配规则 → 反匹配”中修改全局默认，或在单条订阅的“反匹配”页单独覆盖；“跟随全局默认”表示使用全局设置。

新订阅的“基本设置”中可以选择默认启用全局反匹配，或把当前全局反匹配规则复制到新订阅作为本地规则。启用与导入是两种不同方式。

## 通知与模板

支持 Telegram、自定义 HTTP 请求和媒体库刷新通知。邮件、QQ、Server 酱、Bark 等通知方式已移除。

在“设置 → 通知”中可创建和命名多个模板。每个模板选择一种内容类型：

- **普通文本**：用于 Telegram 消息或自定义请求正文，直接使用 `${title}`、`${subgroup}`、`${text}` 等通知变量。
- **JSON**：用于自定义请求正文；JSON 字符串值中的变量会自动转义。
- 自定义请求的 Body 有两种来源：**手写 Body** 直接填写并按 `Content-Type` 发送，**模板作为 Body** 则从模板库选择任意模板，发送时把 `${...}` 替换为真实值；选了模板就忽略手写内容，Content-Type 跟随模板类型。
- 添加通知时先在弹窗中编辑，点击“确定”才会加入列表；关闭或取消不会产生空通知。
- Telegram 只显示普通文本模板；模板删除后，引用它的通知会使用备用模板。

在“设置 → 通知”的“通知状态样式”中可以逐项修改每种状态的表情、名称与事件文案。事件模板支持 `${name}`（资源名或集数，如 `S01E02`）、`${source}`（备用 RSS 标记，普通订阅为空）以及订阅字段如 `${title}`、`${subgroup}`；留空则沿用默认值。

默认文本模板包含事件类型、标题、评分、TMDB / BGM、字幕组、集数进度、首播日期、事件和保存路径。文本和 JSON 模板都直接使用通知变量，例如 `${subgroup}`、`${title}`、`${text}`；JSON 变量需放在字符串值中，例如 `{"subgroup":"${subgroup}","event":"${text}"}`。旧配置中的 `${notification}` 会迁移为旧的完整通知内容。

## 开发者选项

“设置 → 开发者”是独立页面，开启前需要输入当前登录账号与密码，验证通过后立即生效；关闭后其中的设置会保留但不再使用，点击底部“保存设置”后生效。

- **自定义种子地址**：支持 `<info_hash>` 或 `${info_hash}`，未写占位符时会自动追加哈希。程序获得 info_hash 后会替换进地址并请求 `.torrent` 内容；留空则使用 RSS 或种子站提供的原始链接。
- **自定义 User-Agent**：留空使用内置标识 `MintSoda/<版本>`。部分站点按 UA 返回不同内容，排查兼容性时可临时修改；保存时会去掉控制字符并限制长度。
- **请求日志**：开启后记录出站请求的方法、地址、状态码与耗时，不记录请求头与请求体。
- **诊断**：可一键检测到 Bangumi 的连通性，并可跳转日志页或清空当前会话的日志缓存（磁盘日志不受影响）。

## 外观与主题

“设置 → 外观与主题”分为主题与配色、背景与质感、品牌图片、布局与行为、自定义样式五块，右侧常驻主题预览。滑杆、配色、预设与图片改动都会立即作用到整个界面与预览，不需要先保存。

- **主题模式**：跟随系统、浅色或深色。
- **强调色**：可直接选择，也可开启“从背景图动态取色”，程序从应用或登录背景图提取可读的强调色；显式设置的颜色优先。
- **界面质感**：五套预设（蓝白玻璃、樱花粉白、薄荷青白、磨砂雾面、清透极简），一次写入强调色、透明度、模糊度与圆角。预设只改这些已有设置项，不生成额外文件。
- **背景**：应用背景与登录背景都区分浅色与深色，深色留空时沿用浅色。背景本身有独立的模糊度与不透明度，模糊只作用于背景层，不影响文字与控件。
- **质感分层**：卡片、导航栏、弹窗分别可调不透明度与模糊度（亚克力/磨砂效果），另有统一的圆角大小。
- **品牌图片**：登录 Logo 与应用 Logo 可上传或选择已上传资源，清空即恢复默认。
- **布局与行为**：启动页、默认排序、点击封面行为、最大内容宽度与订阅页显示项，保存在浏览器本地。
- **自定义样式**：自定义 CSS、JavaScript 与 WebUI 更新包。

侧栏默认位于右侧，菜单项均分侧栏高度；窄屏下侧栏变为底部导航。

界面支持简体中文（中国大陆）、繁體中文（台灣）与 English。语言选择器位于侧栏底部，登录页与初始化页在右上角；选择保存在浏览器中，首次访问按浏览器语言自动匹配，无法匹配时使用简体中文。切换语言会刷新页面，只影响界面文案。

## 常见问题与排查

**登录后立即被踢回登录页**：令牌有效期由“设置 → 安全与访问 → 登录有效”控制，修改用户名、密码或重新登录会轮换会话。浏览器时间与服务端相差超过 30 分钟时前端会提示时间不同步，请先校准。

**首次启动没有看到初始化页面**：Linux 会直接生成随机凭据并只写一次日志，可用 `journalctl -u mint-soda | head` 或 `mintsoda log` 查找；也可用 `MINT_SODA_USERNAME` / `MINT_SODA_PASSWORD` 覆盖后重启。

**qBittorrent 连接失败**：确认地址含协议与端口、认证方式与 qBittorrent 实际配置一致；在“设置 → 下载与任务”点击测试登录。若启用了 IP 白名单或反向代理信任，确认来源 IP 未拦截。

**订阅没有更新**：依次检查 RSS 间隔是否生效、订阅是否启用、RSS 地址是否可访问、全局排除或反匹配是否拦截、插件过滤器是否拒绝。日志页可看到每轮刷新结果。

**下载了但文件找不到**：确认 qBittorrent 的保存路径与程序配置的下载路径一致，尤其是容器、NAS 或映射盘场景；“已下载文件自动跳过”依赖该路径。

**通知没有发出**：确认该通知处于启用状态、勾选了对应的事件类型、模板类型与 Body 来源匹配；JSON 模板必须是合法 JSON。

**改了外观不生效**：外观改动会立即预览，但只有点击“保存设置”后才写入服务端配置；刷新后恢复未保存前的样式属于正常现象。自定义 CSS/JS 未生效时，可用无痕窗口排除浏览器缓存影响。

**语言切换后部分文字没变**：设置页标签、排序项等常量在页面加载时求值，切换语言会刷新页面重建；若仍未变化，确认该文案是否已抽离为词条。

## 数据与功能范围

MintSoda 提供 qBittorrent 下载、Mikan / AniBT / 手动 RSS 订阅、Telegram / 自定义请求 / 媒体库刷新 / 插件渠道通知、Bangumi 与 TMDB 元数据、重命名与保存路径模板、插件系统，以及可调的主题外观。

| 数据 | 位置 |
| --- | --- |
| 设置 | `config/config.json` |
| 订阅 | `data/subscriptions.json` |
| 封面缓存 | `data/images/covers/` |
| 站点预览图缓存 | `data/images/previews/` |
| 上传的外观图 | `data/images/assets/` |
| 种子缓存 | `data/torrents/` |
| 插件与私有数据 | `data/plugins/` |
| 在线下载的 WebUI | `data/webui/` |
| 自动备份 | `data/backups/` |
| 日志 | `data/logs/MintSoda.log` |

“设置 → 系统与维护”可导出与导入设置备份，备份以 `data/` 为根打包设置、订阅、封面、上传图片、种子与插件（不含 `installed.json`）。迁移到新机器时整体复制 `config/` 与 `data/` 即可。

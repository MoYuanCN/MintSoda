# ANI-RSS-Yuri 使用指南

## 运行与配置文件

ANI-RSS-Yuri 只面向 Windows 和 Linux。发布页提供 Windows EXE 与 JAR，以及 Linux 使用的 JAR。运行 JAR 需要 Java 25。

- **Windows EXE**：配置文件保存在 EXE 同目录下的 `config/`。首次运行会创建该目录。检测到旧版 `%USERPROFILE%/ani-rss/` 配置且目标目录还没有配置文件时，程序会复制旧配置；原目录会保留。
- **Windows 或 Linux 的 JAR**：若设置了 `CONFIG` 环境变量，则使用该目录；否则当前目录存在 `config/` 时使用它。Windows 没有上述目录时使用用户目录下的 `ani-rss-Yuri/`（检测到旧的 `ani-rss/` 配置会自动复制）；Linux 使用当前工作目录下的 `config/`。
- **Linux 一键安装**：`curl -fsSL https://raw.githubusercontent.com/MoYuanCN/ani-rss-Yuri/main/linux/install-yuri.sh | sudo bash` 会把 JAR 安装到执行命令时所在的目录（不新建子目录）并注册 systemd 服务。安装过程中会在终端依次询问用户名与两次密码（密码输入时不回显）：用户名需 3-32 位字母、数字、下划线或连字符，密码至少 8 位且包含大写字母、小写字母、数字、符号中的至少两类；直接回车跳过则由程序在首次启动生成随机凭据。也可用 `--username` / `--password` 直接传入，或用 `--setup` 在尚未配置账号时跳过询问并在 WebUI 中完成初始化，`--port` 修改端口，`--dir` 指定目录，`--yes` 跳过所有确认。安装完成后运行 `assyuri` 打开管理菜单，可查看运行状态、版本、更新、启停和日志，也可直接使用 `assyuri status` 等命令。
- **Linux 固定目录安装**：`sudo bash linux/install-yuri-legacy.sh` 会把服务安装到 `/opt/ani-rss-yuri/`。安装脚本需要联网下载 JAR 和 Java 25。

首次启动不再内置 `admin/admin`：

- **Windows**：程序会自动打开浏览器并显示“初始化登录账号”页面，用户名需为 3-32 位字母、数字、下划线或连字符，密码至少 8 位并包含大写字母、小写字母、数字、符号中的至少两类。完成前无法登录。
- **Linux**：启动时自动生成随机用户名与强密码，并只在首次启动的日志中输出一次；请立即保存，后续启动不会再次显示。
- **环境变量覆盖**：设置 `ANI_RSS_USERNAME` / `ANI_RSS_PASSWORD` 可强制覆盖登录凭据，每次启动都会生效；密码不满足强度要求时程序拒绝启动。

初始化完成后即可登录，再配置 qBittorrent 的地址和认证方式。设置页同样会校验用户名与密码强度，修改后所有已登录会话失效。

## 设置页

设置页的修改只停留在浏览器中，点击底部“保存设置”（或按 `Ctrl + S`）后才会写入配置并生效。

- 顶部标签显示当前状态：`已保存` 或“N 处未保存”；有改动的标签会显示小圆点。
- 底部条常驻显示改动数量，可在保存或切页前随时撤销；`撤销修改` 会丢弃全部未保存改动。
- 设置页顶部搜索框可按页名与关键字（如“间隔”“通知”“代理”）筛选标签，方便定位设置项。
- 保存前会做基本校验：刷新/重命名间隔至少 1 秒，RSS 并发数在 1-16 之间，JSON 模板必须是合法 JSON。
- 账号密码留空表示不修改当前密码；修改用户名或密码后所有已登录会话失效，需要重新登录。
- 有未保存改动时离开设置页会提示确认，确认后这些改动会被丢弃。
- 关于页的开发者选项和 Bangumi 授权回调各自只保存所需部分，不再顺带保存整页设置。

## qBittorrent

在“设置 → 下载”中配置 qBittorrent 地址和认证方式：

- **API Key**：用于支持 API Key 的 qBittorrent 服务。
- **用户名密码**：用于未提供 API Key 的服务，程序使用 qBittorrent WebUI 登录认证。

两种方式互斥。此 Fork 不包含其他下载器，也不提供集成的任务进度页面；任务和进度请在 qBittorrent 中查看。

## 添加订阅

“添加订阅”弹窗提供三种来源：Mikan、AniBT 和“其他”。

- **Mikan / AniBT**：点击“浏览”从站点列表中选择番剧与字幕组，会自动带入 RSS 地址、Bangumi 条目和字幕组。
- **其他**：手动填写番剧名称、Bangumi 地址和 RSS 地址，适合任意第三方 RSS。

同一番剧存在多个字幕组时，可以一次性加入批量确认弹窗，逐条调整后再添加。

## RSS 刷新

在“设置 → 基本设置”中设置 RSS 刷新间隔，单位为秒，最小值为 1 秒。请结合 RSS 站点访问频率和网络环境设置合理间隔。

刷新行为：

- 间隔按“上一轮开始时间”计算，本轮处理耗时不会叠加到等待时间上；若处理时间已经超过间隔，会先短暂停顿再开始下一轮。
- 同一轮刷新会先并发拉取所有 RSS，再逐个订阅做本地解析。并发数可在“RSS并发”中设置，默认 4，范围 1-16；间隔很短时建议保持较小值。
- 相同 RSS 地址在同一轮只请求一次；跨轮会携带 `ETag` 做条件请求，服务端返回 304 时直接复用上次内容。
- RSS 请求失败时会沿用上次成功的内容，并在短时间内退避，避免短间隔轮询持续请求异常站点；没有历史内容时本轮跳过该地址。
- “RSS超时”是单个请求的最长等待时间，默认 20 秒。
- 一轮刷新结束时才统一保存订阅进度，避免短间隔下每个订阅都触发一次写盘。

旧配置中的分钟间隔会自动转换为秒。配置升级后可以在设置页确认刷新间隔。

订阅页顶部提供排序下拉，可临时按评分、拼音、标题、更新时间、更新星期或备用 RSS 数量排序；默认排序在“设置 → 基本设置 → 页面设置”中配置，临时切换不会改动默认值。

## 插件

侧栏“插件”页可以扩展通知渠道、订阅过滤、订阅事件、周期任务、模板变量、下载拦截与插件自有接口。

- **安装**：上传 `plugin.jar`（Java）或 `plugin.zip`（JavaScript / Lua），或在“插件市场”中填写市场索引地址后安装。安装后需手动启用。
- **三种运行时**：Java 插件功能最全；JavaScript 与 Lua 插件不需要编译，适合改模板、加通知渠道与简单过滤。
- **权限**：每个插件卡片有“权限”一栏，按「订阅 / 下载与通知 / 任务 / 接口 / 配置与数据 / 系统」分组逐项开关，读与写分开授权（例如插件可以只读数据不能写入）。取消下载是独立权限，未授权时插件无法中断下载。保存后已启用的插件会立即按新权限重载；关闭的权限对应功能会停止工作，插件其余部分继续运行。安装时按插件声明初始化，升级不会重置你的调整。
- **插件数据**：插件可在自己的 `plugins/{插件标识}/data` 目录保存状态，升级与重装都不会丢失；卸载会连同数据一起删除，需要保留时先导出备份。
- **备份**：导出的设置备份同时包含插件与插件私有数据；导入会整体替换插件目录，插件按备份内容恢复但默认停用，权限仍以本机记录为准。备份文件名形如 `ani-rss-Yuri.backup.<版本>.zip`，日志文件位于配置目录的 `logs/ani-rss-Yuri.log`。
- **市场**：市场地址保存在设置中，是一个 JSON 索引；检查更新时优先使用市场条目，缺少条目时回退到插件自带的更新地址。
- **更新**：插件卡片显示“可更新”与最新版本，可单个更新或一次检查全部插件。
- **配置**：插件可以在插件页声明设置项，保存后会写入插件配置。
- **通知渠道**：启用提供通知渠道的插件后，在“设置 → 通知”的通知类型中选择“插件渠道”，再选择具体渠道并填写其字段。
- **模板变量**：插件可向通知、重命名与下载路径模板追加 `${xxx}` 字段，写法与内置字段一致。
- **下载拦截**：插件可在提交下载器前改写保存位置或名称，也可以直接取消某个任务。
- **插件接口**：插件页会显示插件注册的接口路径，统一挂在 `/api/plugin/api/{插件标识}/` 下，调用需要登录。

安装与更新都会校验 sha256 与文件大小，地址限公网 `http`/`https`。插件与服务同权限运行，只安装可信来源的插件。插件开发方式见 `docs/PLUGIN_DEVELOPMENT.md`。

## 缓存清理

“设置 → 基本设置 → 其他 → 缓存”可以手动清理未被引用的封面与预览缓存。“自动清理缓存”默认关闭，开启后按设定的小时数（默认 72 小时）定期清理，间隔范围 1-720 小时。

## 合集下载

“合集”页上传种子并选择 Bangumi / TMDB 条目后即可下载整季。保存位置会在名称、TMDB、字幕组、季、日期或剧场版标记变化时自动重新计算，也可以点击下载位置旁的刷新按钮手动更新。

“设置 → 下载设置 → 合集保存位置”可以为合集单独指定目录，例如常规保存位置是 `/番剧/更新中`，合集可以保存到 `/番剧/合集`：

- 支持与普通保存位置相同的变量，例如 `${title}`、`${season}`、`${year}`、`${quarterName}`。
- 留空表示不启用，合集使用添加合集时显示的路径；填写的是固定路径（不含变量）时，开始下载会按当前名称重新计算，避免沿用旧名称。
- 启用后，添加合集弹窗中的下载位置输入框只读，并提示正在使用合集保存位置。
- 该设置只影响合集下载，不影响普通 RSS 订阅。

## 重命名和保存路径

全局重命名模板和下载路径可在“设置 → 基本设置 / 下载设置”中修改；单条订阅可以启用自定义重命名模板或自定义保存路径。模板至少保留集数标记 `S${seasonFormat}E${episodeFormat}` 或 `S${season}E${episode}`，避免无法识别剧集编号。启用“已下载文件自动跳过”时，也要确认 qBittorrent 保存路径与 ANI-RSS-Yuri 配置的下载路径一致。

## 标题匹配规则

规则入口包括“设置 → 全局排除 / 全局匹配 / 反匹配”，以及每条订阅的编辑窗口。匹配和排除规则按 RSS 条目标题判断，也可使用 `{{字幕组}}:正则` 限定来源字幕组。反匹配规则单独设置标题正则和目标字幕组：标题命中后，条目会归入该规则指定的字幕组，不要求原 RSS 已带有该字幕组。

### 规则优先级

实际下载和合集预览共用相同的规则判断：

| 顺序 | 规则 | 行为 |
| --- | --- | --- |
| 1 | 本地或全局反匹配命中 | 直接接收条目，并归入命中规则指定的字幕组。该命中优先于普通匹配与排除。多条命中时按规则列表顺序取第一条。 |
| 2 | 反匹配已启用但未命中 | 默认跳过。可在该订阅中改为“继续普通匹配规则”或“直接放行”。 |
| 3 | 订阅本地“匹配” | 配置了多条规则时，每条规则都必须命中。 |
| 4 | 全局匹配 | 仅在该订阅启用全局匹配时生效；每条适用规则都必须命中。全局匹配通过后优先于排除规则。 |
| 5 | 本地排除和全局排除 | 命中任意适用的排除规则则跳过。全局排除需在订阅中启用。 |

反匹配规则之间是“任意一条命中”；本地匹配和全局匹配的规则之间是“每条都命中”。如果没有启用反匹配、全局匹配或排除规则，普通订阅行为不受影响。

### 全局反匹配

在“设置 → 反匹配”中维护共享规则，并用测试区检查标题。之后编辑订阅，在“反匹配”页开启“使用全局反匹配规则”。全局规则不会自动应用到所有订阅。

每条订阅也可维护自己的反匹配规则。两处规则共同生效，任意一条命中即可。反匹配未命中行为按订阅设置，默认是“跳过，不下载”。启用反匹配但没有填写规则时也会按未命中处理。

新订阅的“基本设置”中可以选择默认启用全局反匹配，或把当前全局反匹配规则复制到新订阅作为本地规则。启用与导入是两种不同方式。

## 通知与模板

支持 Telegram、自定义 HTTP 请求和媒体库刷新通知。邮件、QQ、Server 酱、Bark 等通知方式已移除。

在“设置 → 通知”中可创建和命名多个模板。每个模板选择一种内容类型：

- **普通文本**：用于 Telegram 消息或自定义请求正文，直接使用 `${title}`、`${subgroup}`、`${text}` 等通知变量。
- **JSON**：用于自定义请求正文；JSON 字符串值中的变量会自动转义。
- 自定义请求的 Body 有两种来源：**手写 Body** 直接填写并按 `Content-Type` 发送，**模板作为 Body** 则从模板库选择任意模板，发送时把 `${...}` 替换为真实值；选了模板就忽略手写内容，Content-Type 跟随模板类型。
- 添加通知时先在弹窗中编辑，点击“确定”才会加入列表；关闭或取消不会产生空通知。
- Telegram 只显示普通文本模板；模板删除后，引用它的通知会使用备用模板。

默认文本模板包含事件类型、标题、评分、TMDB / BGM、字幕组、集数进度、首播日期、事件和保存路径。文本和 JSON 模板都直接使用通知变量，例如 `${subgroup}`、`${title}`、`${text}`；JSON 变量需放在字符串值中，例如 `{"subgroup":"${subgroup}","event":"${text}"}`。旧配置中的 `${notification}` 会迁移为旧的完整通知内容。

## 开发者选项

“设置 → 开发者”是独立的一级设置页，开启前需要输入当前登录账号与密码，验证通过后立即生效；关闭后其中的设置会保留但不再使用，点击底部“保存设置”后生效。

- **自定义种子地址**：支持 `<info_hash>` 或 `${info_hash}`，未写占位符时会自动追加哈希。程序获得 info_hash 后会替换进地址并请求 `.torrent` 内容；留空则使用 RSS 或种子站提供的原始链接。
- **自定义 User-Agent**：留空使用内置标识 `ani-rss-Yuri/<版本>`。部分站点按 UA 返回不同内容，排查兼容性时可临时修改；保存时会去掉控制字符并限制长度。
- **请求日志**：开启后记录出站请求的方法、地址、状态码与耗时，不记录请求头与请求体。
- **诊断**：可一键检测到 Bangumi 的连通性，并可跳转日志页或清空当前会话的日志缓存（磁盘日志不受影响）。

## WebUI 外观

在“设置 → 基本设置 → 页面设置”中自定义应用背景、登录背景、登录 Logo、应用 Logo，以及卡片、导航栏、弹窗三处的不透明度与模糊度（亚克力/磨砂效果）和圆角大小。背景和 Logo 可上传，也可以选择已经上传的资源。清空图片字段可恢复默认图像。

应用背景与登录背景都区分**浅色模式**和**深色模式**：深色背景留空时沿用浅色背景。背景本身另有独立的**模糊度**与**不透明度**，模糊只作用于背景图层，不会让界面文字和控件发虚。界面卡片、导航栏、弹窗、表格与设置区块默认即使用半透明磨砂质感，背景图会透出在这些区块之下。

默认侧栏位于**右侧**，菜单项均分整个侧栏高度。窄屏下侧栏变为底部导航。

界面支持简体中文（中国大陆）、繁體中文（台灣）、简体中文（Microsoft）与 English 四种语言。语言选择器位于侧栏底部，登录页与初始化页在右上角；选择会保存在浏览器中，首次访问按浏览器语言自动匹配，无法匹配时使用简体中文。切换语言后页面会刷新，只影响界面文案，不会修改任何配置。

主题色可直接选择，也可开启“从背景图动态取色”，程序会从应用或登录背景图提取一个可读的强调色；显式设置的主题色优先。另有五套浅色主题预设（蓝白玻璃、樱花粉白、薄荷青白、磨砂雾面、清透极简），一次套用主题色、透明度、模糊度与圆角。预设只是写入这些已有设置项，不会生成额外文件。

## 数据与功能范围

本分支仅保留 qBittorrent 下载、Telegram / 自定义请求 / 媒体库刷新通知和 Bangumi Token 设置。内置播放、刮削、AnimeGarden、OpenList 上传、Bangumi 点格子、摸鱼检测和 trackers 更新设置均已移除。爱发电页面保留，但本地功能不依赖捐赠状态。

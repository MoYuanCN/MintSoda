# 安全说明

ANI-RSS-Yuri 是自托管的番剧订阅与下载服务，通常部署在家庭网络或 NAS 上，持有管理凭据、下载器凭据和第三方 API Token。本文说明威胁模型、默认安全机制、部署要求与已知限制。

## 支持范围

- 只维护最新发布版本的安全问题；旧版本请先升级再报告。
- 只支持 Linux 与 Windows 的 JAR / Windows EXE 部署；Docker、macOS 与第三方打包不在范围内。

## 报告漏洞

- 请使用仓库的 GitHub Security Advisories（私密安全公告）提交，不要开公开 Issue。
- 报告中请包含：受影响版本、部署方式、复现步骤、影响评估。请勿附带真实的凭据、配置、日志或种子文件；需要时用脱敏样例。
- 修复发布后会在 Release 说明中致谢（如报告者同意）。

## 威胁模型

假设：

- 攻击者可能位于同一网络，或通过端口映射直接访问 WebUI。
- 攻击者可能控制 RSS 源、种子站点、图片 URL 或通知目标，从而影响程序发起的出站请求与解析内容。
- 管理员自身的浏览器与配置目录是可信的；不防御已取得主机权限的攻击者。

重点保护：

- 登录凭据、API Key、JWT 签名密钥、qBittorrent 凭据、Telegram Bot Token、Bangumi / TMDB Token。
- 配置目录中的 `config.v2.json`、备份压缩包、日志、种子与上传文件。
- 对外的更新链路与 WebUI 资源。

## 认证与授权

- 除登录与少量公开接口外，所有 `/api` 接口都通过 `@Auth` 鉴权，支持四种方式：JWT 请求头、表单/查询参数 `s`、API Key、IP 白名单。
- JWT 使用 HS256，签名密钥为随机 32 字节并保存在配置中；有效期由 `loginEffectiveHours` 控制，`0` 表示不过期，默认 3 小时。
- 修改用户名或密码会轮换 `tokenId`，使既有令牌失效；`multiLoginForbidden` 默认开启，新登录会顶掉旧会话。
- `verifyLoginIp` 可选地将会话绑定到登录 IP；`limitLoginAttempts` 默认开启，同一 IP 累计失败 30 次后当日拒绝登录。
- `innerIP` 开启后仅允许内网 IPv4 访问；`reverseProxyTrustIpListEnabled` 开启后只信任名单内代理转发的 `X-Forwarded-For`。
- API Key 可经 `api-key`、`x-api-key` 或 `s` 请求头传递，也可经查询参数 `s` 传递。

### 公开接口

以下接口不需要登录，修改时需评估信息暴露：

- `POST /api/login`、`POST /api/publicSettings`（登录页所需的外观资源名与数值）。
- `GET /api/custom.js`、`GET /api/custom.css`（管理员配置的自定义资源，会注入页面）。
- `GET /api/uiAsset`（仅 `ui-assets` 目录下的图片，路径经过规范化）。
- `POST /api/testIpWhitelist`（返回当前来源 IP 是否命中白名单）。

新增公开接口必须在评审中说明其“不含敏感信息”的理由。

## 部署要求

- 首次启动不再提供默认口令：Windows 引导在浏览器中设置账号，Linux 生成随机强密码并只在首次启动日志输出一次，也可用 `ANI_RSS_USERNAME` / `ANI_RSS_PASSWORD` 强制覆盖。密码至少 8 位且包含大写字母、小写字母、数字、符号中的至少两类，以摘要形式存放。
- 不要把端口直接暴露到公网。需要外网访问时，置于 HTTPS 反向代理之后，并开启 `innerIP` 或 IP 白名单，只信任实际代理地址。
- 保持 `SWAGGER_ENABLED=false`、`MCP_ENABLED=false`，仅在受限网络内临时开启；MCP 端点只接受 API Key。
- `allowCors` 默认关闭。开启后服务会返回 `Access-Control-Allow-Origin: *`，任何站点都可发起跨域请求，仅在确有需要时开启。
- 配置目录包含全部凭据，应限制为服务账号可读写（例如 Linux 安装脚本使用的 `750` 目录与 `640` JAR）。不要将其放入同步盘、公开仓库或共享目录。
- 定期轮换 qBittorrent 凭据、API Key、Bot Token 与 Bangumi / TMDB Token；轮换后确认旧令牌立即失效。
- 备份文件包含完整配置与凭据，导出后请按敏感数据保管。

## 数据处理

- 配置以 JSON 保存在配置目录；`ConfigService#config` 返回给前端时会清空登录密码、下载器密码、JWT 密钥与交易号。
- 前端登录与开发者验证发送的是密码摘要，验证在与保存的摘要比较时完成。
- 日志默认写入配置目录下的 `logs/`，保留 7 天；日志不得记录密码、摘要、API Key、JWT、Bot Token、完整认证头或完整配置。
- 唯一例外是 Linux 首次启动生成的随机登录密码：它只在首次启动写一次日志，用于让用户取回凭据；其余场景（含环境变量覆盖、设置页保存）都不得输出密码。
- 上传文件只保存到配置目录下的 `files/`、`img/`、`ui-assets/`、`webui/`；备份导入写入配置目录。

## 出站请求

- 图片代理（`ProxyImageController`）在请求前调用 `commons/URLUtils#verify`，拒绝 `http`/`https` 之外的协议、`localhost`、`127.0.0.1` 与内网 IPv4 字面地址。
- 更新包与自定义 WebUI 更新必须校验 `size` 与 `sha256` 后才落盘，落盘后才执行替换。
- 自定义种子地址（开发者选项）只校验 `http`/`https` 前缀，属于管理员功能。
- 代理、镜像地址、通知目标都由管理员配置，属于可信输入。

## 上传与文件访问

- 外观图片上传（`/api/uiAsset/upload`）只接受 `png`/`jpg`/`jpeg`/`webp`/`gif`，并校验文件头魔数；读取时限定在 `ui-assets` 根目录内。
- 通用上传（`/api/upload`）只要求登录，按内容摘要命名保存；读取端 `/api/file` 限定图片扩展名。
- 备份导入（`/api/importBackup`）与 WebUI 上传/更新（`/api/webui/*`）会解压到配置目录，改动这些流程时必须确认解压实现能阻止路径穿越（zip-slip），并对条目路径做规范化校验。

## 前端

- API 响应统一为 `Result`，前端在 403 时清空令牌并跳回登录。
- `AboutView` 使用 `v-html` 渲染 GitHub Release 说明，Markdown 渲染开启了原始 HTML。该内容来自仓库 Release，属于受控外部内容；若更换来源或允许用户输入，必须先做净化。
- `/api/custom.js` 与 `/api/custom.css` 由管理员写入并注入页面，等同管理员拥有脚本执行能力；不要允许非管理员修改这两个配置项。

## 已知限制

以下是当前实现的风险点，改动相关代码时应优先修复，至少不得扩大：

1. 摘要传输：登录与开发者验证在客户端计算摘要，等价于口令本身可重放；首次初始化的 `/api/setup` 只允许本机或内网调用并接收明文以校验强度。必须配合 HTTPS 反向代理使用。
2. 文件接口路径：`/api/file` 在登录后按给定的 Base64 路径读取本地文件，仅以图片扩展名作为限制，绝对路径也不受限。应改为限定在配置目录范围内。
3. SSRF 覆盖不完整：`URLUtils#verify` 不解析域名、不阻止 IPv6 回环与内网地址，且 HTTP 客户端会自动跟随重定向，存在 DNS 重绑定与重定向绕过空间。图片代理与自定义地址应增加解析后地址校验与重定向限制。
4. 明文 HTTP：默认以 HTTP 提供 WebUI，凭据与令牌在链路上未加密。
5. 外部二进制依赖：Windows 打包会在资源生成阶段下载 `ani-rss-update.exe`（未入库，未校验哈希），并作为更新器嵌入产物。发布构建应固定来源与校验值。
6. 公开自定义资源：`custom.js` / `custom.css` 无需登录即可读取，未限制响应头与内容类型之外的防护，配置内容会直接影响所有访问者。
7. 解锁文件与配置不加密：配置文件、备份与日志均以明文保存，依赖主机与目录权限保护。

## 安全变更要求

提交涉及认证、文件、网络请求、解压、模板渲染或依赖升级的改动时：

- 说明攻击面变化与新增的信任边界。
- 不为方便而放宽既有校验（URL 校验、扩展名与魔数校验、`startsWith(root)` 路径限制、大小与哈希校验）。
- 不新增记录敏感值的日志；调试信息用掩码或摘要。
- 依赖升级后检查是否有已知漏洞，并确认 JAR 与 EXE 仍能构建。
- 更新本文件中的“已知限制”或默认值说明，保持与实现一致。
